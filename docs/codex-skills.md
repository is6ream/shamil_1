## Адаптации и Windows

- В копиях дизайн-скиллов сужены description и область применения, пути `.claude/skills/<name>` заменены на `.agents/skills/<name>`. Impeccable — основной для доработки/проверки UI, ui-ux-pro-max — точечная справка, design-taste-frontend — только явно заказанный редизайн публичных страниц. Инструкции не требуют применять их одновременно.
- У Impeccable Claude-специфичные `argument-hint`, `user-invocable`, `version` перенесены в metadata; исправлена исходная неверная ссылка в `reference/degraded/asset-producer.md`. Все немаркетинговые рекомендации подчинены правилам проекта и запросу.
- Добавлен `.agents/skills/playwright/scripts/playwright_cli.ps1`: PowerShell-аналог штатного Bash-wrapper с поддержкой PLAYWRIGHT_CLI_SESSION. В SKILL.md указан новый путь; глобальный пакет и зависимости приложения не устанавливались. Первый запуск использует npm cache.
- У prisma-cli явно обозначены отсутствующие необязательные соседние скиллы prisma-orm-setup, prisma-compute, prisma-postgres-setup. Неработающая ссылка на prisma-orm-setup заменена текстовым указанием. Они не требуются для установленного справочника ORM 7 и не устанавливались сверх запроса. Проект использует Prisma 7.10.0; upstream metadata справочников — 7.9.1, поэтому конкретные API сверять с установленной версией.
- Impeccable engine 0.1.8 загружен штатным Windows launcher с проверкой SHA256 в `.cache/impeccable`. Перед запуском из корня: `$env:IMPECCABLE_HOME = Join-Path (Get-Location) '.cache/impeccable'`. Затем `& '.agents/skills/impeccable/scripts/impeccable.cmd' engine-probe`. При очистке кеша launcher потребует повторную загрузку.
- Python 3.13.2 и Node 22.12.0 доступны. Для bundled quick_validate установлен PyYAML 6.0.3 только в `.cache/skill-validation`, не в зависимости приложения. В PowerShell: `$env:PYTHONUTF8='1'` и `$env:PYTHONPATH=Join-Path (Get-Location) '.cache/skill-validation'` перед запуском валидатора.
