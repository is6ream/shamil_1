# Анализ репозитория перед админ-панелью

Дата: 07.10.2026. Ветка `feature/admin-panel` от `chore/vercel-demo` (`eb72ce9`).

## 1. Стек и структура

| Что | Факт |
| --- | --- |
| Монорепо | npm workspaces (`apps/api`, `apps/web`), один `package-lock.json` |
| Node | `>=22.12.0` (локально 22.12.0), npm 10.9 |
| Бэкенд | NestJS 11, `@nestjs/config` 4, `@nestjs/throttler` 6.5, helmet 8, class-validator 0.15 |
| ORM / БД | Prisma 7.10 (драйвер-адаптер `@prisma/adapter-pg`), PostgreSQL 17 (Docker Compose локально) |
| Фронтенд | Next.js 16.3 (App Router), React 19.2, без UI-фреймворков, CSS Modules |
| Тесты | Jest 30 + ts-jest, тесты схемы на реальной БД (`TEST_DATABASE_URL`), e2e на supertest и живом порту |
| Линт | ESLint 9 flat config в обоих приложениях |

Модули API: `config`, `database` (Prisma + сиды), `donations`, `payments` (интерфейс провайдера,
Robokassa, manual, эмулятор), `admin` (одно действие, статический токен), `showcase` (публичные чтения),
`health`.

Схема БД: `campaign`, `campaign_stats`, `campaign_monthly_goal`, `region`, `region_stats`, `donation`,
`donation_contact` (ПДн отдельно), `payment_event` (идемпотентность), `gallery_item`. Целостность сумм держат
триггеры и CHECK во второй миграции: `pending → paid` финально, витрины пересчитывает
`donation_stats_sync`, оплаченный донат удалить нельзя. **Вставка доната сразу в `paid` триггером
учитывается** — на этом строятся ручные поступления.

## 2. Аутентификация сейчас

Одна админская ручка `POST /api/admin/donations/:id/confirm` за статическим `ADMIN_API_TOKEN`
(Bearer, сравнение за постоянное время по SHA-256). Пользователей, ролей и сессий нет.

## 3. Robokassa: аудит ResultURL

Проверено по коду `payments/`:

| Требование | Состояние |
| --- | --- |
| Подпись паролем №2 с `Shp_` по сортировке имён | есть, `signature.ts`, покрыто тестами |
| `timingSafeEqual` | есть, регистронезависимо |
| Подпись до разбора тела, неподписанный — 401 без записи в БД | есть |
| Заказ создаётся до редиректа, `InvId` — последовательность БД | есть (`invoice_no`) |
| Идемпотентность | уникальный `(provider, provider_event_id)` + перечитывание статуса в транзакции |
| Success/Fail URL статус не меняют | да, «спасибо» только опрашивает статус |
| Секреты из env с валидацией на старте, не в логах | да; почта плательщика вырезается из `payload` |
| Rate limit на колбэке | снят намеренно (`@SkipThrottle`), защита — подпись |

**Расхождение суммы.** Колбэк с суммой, отличной от заказа, сейчас зачисляется по факту оплаты
с предупреждением в лог. `OutSum` входит в подпись паролем №2, то есть сумма подлинная — это реально
списанные деньги. Отказ от них оставил бы деньги на счёте без доната. Поведение оставлено, добавлено
оповещение в Telegram (решение D-03).

Уязвимостей в обработке ResultURL не найдено. Улучшения в этой ветке: Telegram-оповещение о колбэке
с неверной подписью и о расхождении суммы.

## 4. Прочий аудит безопасности

- helmet, CORS по списку из env (`credentials: true`), глобальный `ValidationPipe`
  (`whitelist`, `forbidNonWhitelisted`, `transform`), глобальный throttler — уже есть.
- `.env` в git не отслеживается (`.gitignore`), в репозитории только `.env.example`.
- **Найдено: `.gitignore` правилом `build/` скрывает `apps/web/components/build/`** (таймлайн стройки,
  видео, блок хода строительства). На GitHub этих файлов нет — чистый клон фронтенда не собирается.
  Исправлено первым коммитом ветки (`/build/` только в корне и `apps/*/build/`).
- Логи запросов Prisma выключены (ПДн в параметрах) — сохраняем.

## 6. Медиа

Хостинга медиа нет: галерея хранит `image_url` строкой, фото пока не загружались. `next.config.ts`
не разрешает внешние картинки (`images.remotePatterns` пуст) — для медиатеки нужно добавить домен API.

## 7. Как фронт получает контент

Серверные компоненты, `fetch` с `next.revalidate` (15 с для цифр, 3600 с для справочников), запасные значения
через `withFallback`, если бэкенд лежит. Тегов кеша нет — для ревалидации из админки добавляем
`next.tags`.

## 8. Ограничения хостинга reg.ru / ISPmanager

Docker, Redis и брокеров не закладываем. Новые нативные зависимости: `sharp` (готовые бинарники для linux-x64
glibc). На shared-хостинге с musl или без прав на postinstall может не встать — см. REPORT.md, раздел деплоя.
