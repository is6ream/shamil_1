- **S3 на реальном бакете не проверялся** — нет ключей. Код драйвера покрыт только тем, что собирается; e2e

  отдельной стадией с `npm prune` и вынесенным prisma — не критично.

## Безопасность

- Все `/api/admin/*`, кроме `login`/`logout`/`refresh`, без Bearer — 401: e2e перебирает **все** маршруты
  из роутера приложения, новый незакрытый маршрут уронит тест.
- IDOR: в админке нет «своих» и «чужих» объектов кроме пользователя; права проверяются ролью на каждом маршруте,
  роль читается из БД на каждом запросе. Свой профиль — только через `me`/`password`, по id из токена.
- CORS — список из `CORS_ORIGINS`, `credentials: true`; чужой origin ответа не получает (e2e).
- `npm audit --omit=dev`: в **новых** зависимостях (`sharp`, `@aws-sdk/client-s3`) high/critical нет —
  `sharp` поднят до 0.35.5 (lock уже требовал её). Остаются high/critical в **существующих** зависимостях:
  `next` (фронт, critical: cache poisoning, SSRF в Image Optimization — фикс в next 16.4.0), `prisma` CLI
  (`@prisma/config` → `deepmerge-ts`, `mysql2`), `source-map-js`. **Требует решения человека** — обновление
  `next` вне диапазона версий и за пределами бэкенда.

## Отклонения от промпта

- **`@nestjs/jwt` понижен с 12 до 11** (D-18): 12 — ESM-only для Nest 12, Jest на CJS её не грузит.
- **Ревалидация шлёт `Authorization: Bearer`**, а не произвольный заголовок секрета — так требует уже
  написанный фронтом `/api/revalidate` (D-F02).
- `PATCH /admin/auth/password` — по промпту; фронт предварительно ждал `POST` (D-F01) — сверить по API.md.
- Длина пароля — от 12 символов (фронт предварительно взял 10, D-F03).
- Сид больше не перетирает `campaign.goal_kopecks` при повторном запуске: цель теперь правится в админке (D-29).
- Работа шла параллельно с фронтенд-агентом в одной рабочей копии: его незакоммиченные правки в
  `docs/admin/*.md` и `apps/web` в коммиты бэкенда не попадали (документы стейджились поверх версии из HEAD).
