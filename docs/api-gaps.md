# Витринные эндпоинты: контракт фронтенда и бэкенда

Составлено 21.09.2026 при сборке главной в двухколоночной раскладке.
**Реализовано 27.09.2026** (`apps/api/src/showcase/`): фронтенд
(`apps/web/lib/api/showcase.ts`) ходит в эти эндпоинты, моков цифр больше нет.
Все ручки — публичные `GET` без троттлинга (SSR Next.js ходит с одного IP).

### Решения по умолчанию — ждут подтверждения заказчика

- **Топ донатеров — по одному платежу**, а не по сумме от человека (§4):
  другого ключа человека, кроме телефона из таблицы ПДн, нет.
- **`donorsCount` в рейтинге регионов = число платежей**, не людей (§3).
- **Цель месяца — заглушка из сидов** (5 000 000 ₽), пока заказчик не назовёт сумму.
- **Fail URL → главная** (docs/robokassa-activation.md, блок 4).

Общие правила, которые должны сохраниться:

- **суммы — строки копеек.** В базе это `BigInt`, а `JSON.stringify` на нём бросает
  исключение; конвертация явная, в мапперах (как в `donation-response.dto.ts`);
- **ПДн наружу не выходят.** Телефон и `fullName` не попадают ни в одну публичную
  выборку — это требование 152-ФЗ и причина, по которой они лежат отдельной таблицей;
- **лента листается keyset-курсором** по `(paid_at, id)`, без `OFFSET`: у референса
  пагинация на 2388 страниц, и это не ошибка вёрстки, а `OFFSET` на большой таблице.

## 1. `GET /campaign`

Двойной прогресс-бар и компактные цифры над формой. В базе уже есть `campaign_stats`
и `campaign_monthly_goal`.

```json
{
  "goalKopecks": "24000000000",
  "collectedKopecks": "1284000000",
  "donationsCount": 1204,
  "lastPaidAt": "2026-09-21T11:27:00.000Z",
  "monthlyGoal": {
    "goalKopecks": "600000000",
    "collectedKopecks": "430000000",
    "periodStart": "2026-09-01T00:00:00.000Z",
    "periodEnd": "2026-09-30T23:59:59.000Z"
  }
}
```

`periodStart` / `periodEnd` — начало первого и последняя миллисекунда последнего
дня периода **по Москве** (та же зона, что у триггера витрин): для сентября это
`2026-08-31T21:00:00.000Z` … `2026-09-30T20:59:59.999Z`.

**`monthlyGoal` должен быть nullable.** Заказчик ещё не назвал сумму и период
(открытый вопрос из `handoff.md`), а активной цели месяца может не быть и потом —
между периодами. Фронтенд в этом случае показывает одну общую шкалу; присылать
вместо неё нули нельзя, «0 из 0» читается как поломка.

`lastPaidAt` тоже nullable — до первого платежа.

## 2. `GET /regions`

Селектор «Откуда вы?». Порядок сортировки — как в индексе `region(type, sort_order, name)`.

```json
[{ "slug": "bashkortostan", "code": "02", "name": "Башкортостан", "type": "subject", "flagUrl": null }]
```

Отдавать только `is_active`. «Россия» в списке нужна (её можно выбрать), хотя в рейтинг
она не идёт по `is_ranked`.

## 3. `GET /regions/top`

```json
{ "items": [{ "slug": "02", "name": "Республика Башкортостан", "flagUrl": null, "donorsCount": 412, "paidTotalKopecks": "73589000" }], "emptyCount": 64 }
```

Только `is_ranked` и `is_active` с поступлениями, по `paidTotalKopecks` убыванием, лимит 10.
`emptyCount` — ранжируемые активные регионы без поступлений (строка «Ещё 64 региона
ждут первого пожертвования»). `donorsCount` — число **платежей** (решение по умолчанию).

## 4. `GET /donors/top`

```json
[{ "donorName": "Наиль Х.", "paidAmountKopecks": "5000000" }]
```

Только `is_anonymous = false` и только `paid`. Открытый вопрос, влияющий на этот
запрос: **топ по одному платежу или по сумме от человека?** Личного кабинета нет,
единственный надёжный ключ человека — телефон, а он в таблице ПДн.

## 5. `GET /donations/feed?cursor=&limit=`

`limit` 1…50, по умолчанию 6. Битый курсор или лишний параметр — 400.

```json
{
  "items": [{
    "id": "e2f1…",
    "paidAt": "2026-09-21T11:32:00.000Z",
    "amountKopecks": "10000",
    "method": "sbp",
    "regionName": "Башкортостан",
    "donorName": null
  }],
  "nextCursor": "eyJwYWlkQXQiOiIyMDI2…"
}
```

**`id` в элементе — добавка к первоначальному контракту.** Он нужен как стабильный
React-`key`: без него строки ленты пересоздаются при догрузке следующей страницы.
Публичный uuid доната для этого годится, номер счёта провайдера наружу не нужен.

`donorName: null` у анонимного доната — это большинство ленты, фронтенд показывает
«Аноним». `method` — значение `donation.method` как есть (`sbp`, `card`, `sberpay`,
`tpay`, `bank_transfer`, `cash`), человекочитаемые названия подставляет фронтенд.

Курсор для фронтенда непрозрачен: он возвращает его как есть, не разбирая.

## 6. `GET /gallery`

```json
[{ "id": "…", "url": "/uploads/2026-06-foundation.webp", "caption": "Заливка фундамента", "takenAtLabel": "июнь 2026" }]
```

Порядок — `sort_order`, затем `taken_on` по возрастанию, с самых первых этапов —
требование ТЗ. Пустой массив — фронтенд показывает плашки с датами.

## 7. Чего НЕ просим

- **Счётчики репостов.** Серверный счётчик тут же начнут накручивать, а ценность
  у него только психологическая. В MVP он живёт в `localStorage` браузера.
- **Ход строительства.** В MVP это статический контент от заказчика, не таблица.

## `channel` в `POST /donations` — реализовано 27.09.2026

`channel?: "online" | "transfer"` (`@IsIn(PAYMENT_CHANNELS)`). Провайдер выбирается
по донату (`PaymentProviderResolver`):

- `transfer` → всегда `ManualProvider`, `redirectUrl` = `/donate/transfer?order_id=…`;
- `online` → онлайн-агрегатор; при `PAYMENT_PROVIDER=manual` — 400
  «Онлайн-оплата временно недоступна — переведите по реквизитам», заказ не создаётся;
- без поля → провайдер из `PAYMENT_PROVIDER`, как раньше.

Фронтенд кладёт `channel` в тело и всегда идёт по `redirectUrl`.
