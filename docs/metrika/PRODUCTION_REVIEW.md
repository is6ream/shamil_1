## Исправления ревью и проверки переноса

- При входе в `/admin/**` — `destruct`, очистка отложенных вызовов до загрузки tag.js,
  сброс трекера страниц. При возврате — повторный init и hit. ClientID не возвращается
  из старого кэша при недоступном/запрещённом счётчике.
- API читает source_quantity/line_quantity. При неполном или неизвестном принятии —
  FAILED всей неоднозначной пачки, uploading_id сохранён, last_error с количествами,
  ERROR в журнале. Никакого PROCESSED или автоматической повторной отправки такой пачки.
  Подробности ручной сверки — DEPLOY.md.
- SAVEPOINT охватывает и чтение идентификаторов, и запись outbox. Ошибка аналитики
  не откатывает платёж и payment_event. Тексты Prisma/HTTP-ошибок с данными не логируются.
- Хиты фильтруют query до нормализованных UTM/цифрового yclid, внешний referer — без query.
- Подписи донатеров в публичной ленте и топе помечены `ym-hide-content`,
  поля имени и телефона — `ym-disable-keys`.
- Показ формы считается при фактических 50% видимости, без изменения поведения
  существующих вызовов анимационного хука.
- Исправлены два блокера проверки production-базы: parentId в фикстуре теста рейтинга
  и async-обёртка Web Locks для совместимости типов TypeScript. Продуктовые правила не менялись.

## Публикация и ограничения

Push в production запускает Timeweb (это также зафиксировано в CI исходной ветки).
По условию текущей задачи требуется отдельное согласование до push. Деплой и настройки
провайдеров не выполнялись. Успех локальных проверок не доказывает работу боевого счётчика.

Владелец: создать счётчик, JS-цели из GOALS.md, включить офлайн-конверсии, выдать OAuth
с доступом к счётчику. Frontend build: NEXT_PUBLIC_YM_ENABLED, NEXT_PUBLIC_YM_COUNTER_ID,
NEXT_PUBLIC_YM_REQUIRE_CONSENT (true), NEXT_PUBLIC_YM_WEBVISOR. API runtime:
YM_OFFLINE_ENABLED, YM_COUNTER_ID, YM_OAUTH_TOKEN, YM_OFFLINE_GOAL (donation_paid),
YM_OFFLINE_INTERVAL_MINUTES (30). Токен хранится только в окружении хостинга.

До включения остаются вопросы владельца из CHECKLIST_OWNER.md: текст политики,
модель согласия, Вебвизор и доступный пользователю способ отзыва согласия (интерфейса
отзыва пока нет). first/last-touch и yclid по принятой исходной модели работают
независимо от согласия на загрузку счётчика. Частично принятые пачки требуют ручной сверки.
Реальные платежи, реальные события Метрики и состояние production-деплоя не проверялись.
