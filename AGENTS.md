## Проверки (PowerShell, из корня)

Выбирайте проверки по изменению; для инструкций достаточно проверки файлов и ссылок.

```powershell
npm run lint
npm run test --workspace @shamil/web
npm run test --workspace @shamil/api -- --runInBand
npm run typecheck --workspace @shamil/api
npx tsc --noEmit -p apps/web/tsconfig.json
npm run build
git diff --check
```

API pretest/prebuild запускают Prisma generate. Интеграционные тесты требуют выделенной тестовой PostgreSQL и `TEST_DATABASE_URL`; пропущенные тесты не считать успешной проверкой БД.

При работающих локальных серверах: `node scripts/smoke-test-payment.mjs` (пишет тестовые платежи), `node scripts/e2e-admin.mjs` (меняет тестовые данные). Только тестовое окружение, платежный эмулятор и тестовые учётные записи. Адреса задаются `$env:SITE_URL` и `$env:API_URL`; проверьте их до запуска. `node scripts/preview-palette.mjs` по умолчанию ожидает сайт на localhost:3001, тогда как README — на 3000; явно задайте `$env:SITE_URL`. Для новых снимков задайте `$env:PALETTE_OUTPUT_DIR` во временный каталог, чтобы сохранить прежние артефакты.

## Инварианты

- Для добровольных безвозмездных пожертвований на строительство мечети «Шамиль» фискализация не требуется. Это правило действует для разовых и регулярных пожертвований, включая первый и все последующие платежи. Кассовые чеки не формируем, `Receipt` и данные СНО в Robokassa не передаём, фискализацию магазина не подключаем. [Разъяснение ФНС о добровольных пожертвованиях](https://www.nalog.gov.ru/rn39/ifns/imns_39_26/events/13710261/).
- Деньги — целые копейки; подпись и идемпотентность обязательны. Онлайн-платёж подтверждает серверный callback; редирект и таймаут UI ничего не доказывают. Ручной перевод подтверждается отдельным защищённым путём проекта. Учитывайте SQL-триггеры и поздние события. Для проверки никаких реальных списаний.
- Хадисы и религиозные тексты не придумывать и не публиковать без выверки заказчиком/имамом. Сохранять существующий контент, фото и пользовательские изменения. Старые юридические положения — решения проекта, не независимо проверенное юридическое заключение.
- Базовые токены: `docs/design/tokens.css` и копия `apps/web/app/tokens.css`. Публичные переопределения: `apps/web/app/public-palette.css`. Сохранить отдельную тему админки и серверный маркер `data-admin-theme`; не переносить золотую тему в админку.
- До выпуска установить фактические целевые ветку, окружение и diff. Не переносить WIP целиком по названию ветки. Не включать секреты, временные файлы, `_to_delete/`. Ничего не публиковать лишь потому, что установлен release-скилл.

## Git

Сохраняйте чужие и существующие изменения, не используйте массовый add без просмотра состава. По CLAUDE.md после завершения и проверки работы спросите ровно один вопрос: **«Пушим в GitHub?»**. Без соответствующего согласования не делать commit/push. D-20 в DECISIONS.md относится к отдельному историческому заданию админки, а не к постоянному разрешению коммитить. Установка скиллов разрешена текущей задачей; публикация сайта — нет.
