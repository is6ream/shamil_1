## Проверка безопасности и отображение

Все три подключённых файла разобраны XML-парсером и проверены по списку допустимых
графических элементов. В `sbp.svg` только `svg`, `path`; в `tpay.svg` — `svg`, `path`; в `sberpay.svg` —
`svg`, `g`, `path`. Отсутствуют `script`, обработчики `on*`, `foreignObject`,
`image`, `use`, ссылки `href`/`src`, внешние ресурсы, `style`, CSS-импорты,
анимация, DTD/ENTITY, XML-стили, `javascript:` и `data:`. Ссылок `url()` нет.
Результат: **все три файла безопасны для подключения как изображения**.

Байты оригиналов, цвета, viewBox, пропорции и внутренние поля сохранены;
SVG не оптимизировались и не редактировались. Next Image используется с
`unoptimized`, пустым `alt` (название уже есть в radio-подписи), точными
исходными размерами и `object-fit: contain`. Нет `filter`, маскирования или
`overflow: hidden` для логотипов. Внешний контейнер оставляет свободное поле.

Новые артефакты проверки находятся отдельно от прежних:
`output/playwright/payment-logos-2026-11-03/`; дополнительная проверка всех трёх знаков —
`output/playwright/tpay-2026-11-03/` (локальные незакоммиченные артефакты).
Форма проверяется без отправки; браузерный сценарий дополнительно блокирует
все POST-запросы. Для T-Pay проверяется оригинальная капсула сервиса.
